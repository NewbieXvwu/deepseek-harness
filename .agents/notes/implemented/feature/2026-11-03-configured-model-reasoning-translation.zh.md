# Agent Note: Reasoning translation can use one configured model route

Status: implemented

[English](2026-11-03-configured-model-reasoning-translation.md) | 中文

## 问题

[付费原生 Flash 决策](../architecture/2026-10-05-paid-native-flash-reasoning-translation.zh.md) 曾把基于模型的翻译限制在两条 DeepSeek 内置凭据路由上，因为把片段发往任意已配置模型会隐藏接收方以及为它付费的计费面。因此，通过 OpenAI 或 Anthropic 兼容网关、自建端点，或 [`dsh-llm-pi-ai`](../../../../packages/llm/llm-pi-ai/README.zh.md) 注册的其他路由进行对话的部署，完全没有基于模型的翻译，而已经信任该路由承载对话的读者也无法把这份信任延伸到思考内容展示。当初促成该限制的事实，如今在已发布的组合中有了对应物：模型页为每条可配置路由登记各自的凭据引用与模型目录，于是接收方是一个具名的部署选择，而不是一个开放式字符串；而思考过程翻译面板正是读者接受费用的位置。

## 决策

翻译在 `deepseek-account` 与 `deepseek-official` 之外提供第三个付费选项 `llm`。读者在同一个披露计费的面板中，从 Host 的模型目录选择一对 `(provider, model)`；该选择以翻译服务条目的可变字段 `llmProvider` 和 `llmModel` 保存，因此本部署中所有翻译服务消费者共用这一条已配置路由。两个名称都为空时，只要存在某个不占有那些保留身份的已注册提供方，发现流程就列出 `llm`，因为路由的首次选择正是在这个面板里发生的；一旦保存了名称，它必须指向一条真实可用的路由才会再次列出。

只有当这对名称指向一条真实可用的路由时请求才合格：提供方已注册到 `ctx.llm`，其 Loader 条目处于活动状态，声明它的配置段所指定的凭据已配置（或根本没有指定凭据），并且该提供方的模型目录中存在精确匹配的模型 id。`google`、`bing`、`deeplx`、`deepseek-account`、`deepseek-official` 作为路由名称一律拒绝，因此每个计费面只保留一个身份。准入在凭据与目录读取之后、派发之前重新检查，并在请求记录持久化之后再次检查，因为持久存储可能活得比被准入的路由更久。

思考强度按模型协商：模型支持 `off` 就关闭，否则使用它所声明的最低强度，否则完全不发送思考控制。仍会思考的模型，其推理输出被丢弃——不拼接、不保存、不展示——但提供方照样计费，面板在保存该选择之前就说明了这一点。

片段本身、固定的直译指令，以及不提供历史和工具，都与内置路由一致，因此缓存译文在各路由之间只在形式上可比，不在标识上可比：模型路由的翻译规则携带提供方与模型 id，而两条内置路由的规则与本次选择之前发布时逐字节相同。所以升级不会重复计费已保存的内置译文，已保存的译文也绝不展示给另一个模型。

## 考虑过的替代方案

**复用对话自身的模型路由。** 它的历史、压缩状态与生成控制属于另一个请求，翻译器的单片段契约需要逐提供方重新界定。具名路由让查询保持为一个片段加一条指令。

**只配置一个自由填写的模型名而不配提供方。** 模型 id 在不同提供方之间会重名，而决定资格的凭据与目录事实都按提供方存在，因此这一对才是最诚实的最小地址。

**把任何推理输出当作无效响应。** 忽略思考开关的网关会让所有无法关闭思考的模型每个片段都失败，而在支持推理的目录中这类模型占多数。丢弃输出并披露其代价，让这些路由仍然可用。

**把内置 Flash 路由扩展到任何上报 `deepseek-flash` 模型的提供方。** 那会把计费从显式选择的 DeepSeek 凭据悄悄转移到应答的那个路由，正是先前决策所拒绝的隐藏行为。

**已配置路由不可用时默认回到 Bing。** 已为某片段接受付费翻译的读者，会在没有请求的情况下得到另一个接收方的输出。`availableProviders()` 改为撤回该选项，而保存的结果仍可读取。

## 后果

配置了该路由的部署为每个未缓存片段付费，且无法关闭的思考会被隐形计费；面板提示与按模型区分的翻译规则就是披露方式。更换模型会重新翻译，因此改写路由需要再次付费。模型目录发现会解析所有提供方的模型，所以面板只在 Host 提供 `llm` 时读取它，且排在内置路由之后；读取缓慢或失败时撤回该选项，而不是让整个列表失败。可变字段无法保留 schema transform，因此地址与路由名称在请求读取时校验，而不是在文档解析时。任何路由都不会回退到另一个路由；本注意只取代「只提供两个内置标签」这一拒绝，内置路由对精确 `deepseek-flash` 目录成员的要求、其凭据检查，以及不让已配置路由共享该身份的决定都维持原样。
